How to Contribute

How to Contribute

We welcome contributions from the community! Whether you’re fixing typos, improving examples, or adding new workshops, your help makes these resources better for everyone.

Ways to Contribute

1. Report Issues

Found a bug or unclear instruction?

  • Check existing issues first to avoid duplicates
  • Describe the problem clearly with steps to reproduce
  • Include your environment (OutSystems version, OS, browser)

2. Improve Content

Help us enhance existing workshops:

  • Fix typos and grammatical errors
  • Clarify confusing sections
  • Update outdated information
  • Add missing code comments

3. Add Examples

Share working code and use cases:

  • Create a new example following our structure
  • Include detailed comments explaining each step
  • Test thoroughly before submitting
  • Document dependencies and prerequisites

4. Create New Workshops

Propose a new workshop topic:

  • Align with the OutSystems platform
  • Target a clear learning outcome
  • Follow our template for consistency
  • Include hands-on exercises

Contribution Process

Step 1: Fork or Branch

# Clone the repository
git clone <repository-url>

# Create a feature branch
git checkout -b feature/your-contribution-name

Step 2: Make Your Changes

  • Follow our style guide
  • Keep changes focused and atomic
  • Test your changes locally
  • Update relevant documentation

Step 3: Commit with Clear Messages

git commit -m "Fix: Correct outdated MCP example in workshop 5"
git commit -m "Docs: Add missing prerequisites section"
git commit -m "Feature: Add new workshop on advanced connectors"

Step 4: Submit Pull Request

  • Describe your changes clearly
  • Reference any related issues
  • Include before/after for significant changes
  • Request review from maintainers

Style Guide

Content Standards

  • Language: Clear, professional English
  • Code: Well-formatted with consistent indentation
  • Examples: Tested and working
  • Images: High-quality, properly captioned

Markdown Format

# Main Heading

## Section Heading

### Subsection

**Bold text** for emphasis
`code` for inline code

Code Examples

// Always include language identifier
// Add comments explaining the code
function example() {
  return "formatted correctly";
}

Review Guidelines

Your contribution will be reviewed for:

  • Accuracy - Is the information correct?
  • Clarity - Is it easy to understand?
  • Quality - Does it meet our standards?
  • Completeness - Are there missing pieces?

Reviewers may request changes. This is normal! Collaborate with us to get your contribution merged.

Licensing

By contributing, you agree that your contributions are licensed under the same license as the project. All contributions are valuable, and we appreciate your effort.

Code of Conduct

We’re committed to providing a welcoming and inclusive community. Please:

  • Be respectful and constructive
  • Welcome diverse perspectives
  • Focus on ideas, not personalities
  • Help others learn and grow

Getting Help

  • Questions? Start a discussion in the repository
  • Stuck? Ask in comments on the issue or PR
  • Ideas? Share in our community forum

Recognizing Contributors

Contributors are recognized in:

  • Commit history
  • Release notes for significant contributions
  • Contributors page on the website

Thank you for helping us build better learning resources!
